ASTRA AI Course Builder

Branch: feature/ai-course-builder Feature summary 29 Jul 2026

This document explains all changes made for the AI Course Builder feature, how they were implemented, and how teachers and students use the flow.

1. Goal

Let a teacher upload a syllabus, let AI generate a roadmap, flashcards, quiz, and assessments, then require teacher review/publish before students can see that content.

Teacher uploads syllabus → AI generates draft artifacts → Teacher reviews / edits → Teacher publishes selected artifacts → Students see only published content

2. AI stack chosen

ChoiceWhy

Provider-agnostic interface Can swap to OpenAI / Claude / local models later without rewriting routes
Mock provider fallback Works without an API key during local development
Teacher-review publish model AI drafts never go directly to students

5. How the backend works

5.1 Data model

  • CourseBuildJob — tracks generation status (PENDING, RUNNING, COMPLETED, FAILED), requested artifact types, syllabus snapshot, errors.
  • CourseArtifact — stores each generated piece (roadmap, flashcards, quiz, assessment) as JSON, with is_published defaulting to false.

5.2 API endpoints

MethodPathWhoWhat it does
POST /subjects/{id}/course-builder/upload-syllabus Teacher Uploads syllabus file; stores path; extracts text for txt/md
POST /subjects/{id}/course-builder/generate Teacher Creates a job and runs generation in a background task
GET /subjects/{id}/course-builder/jobs/{job_id} Teacher Polls job status
GET /subjects/{id}/course-builder/artifacts Teacher / Student Teachers see drafts + published; students see published only
PATCH /course-builder/artifacts/{artifact_id} Teacher Edit title/content and toggle publish

5.3 Permissions

  • Edit/generate/publish: SUPER_ADMIN, class teacher of the classroom, or subject teacher of that subject.
  • Students must be enrolled and the subject must be published; they only receive artifacts with is_published=true.

5.4 Generation pipeline

  1. Teacher ensures syllabus text exists or uploads a file.
  2. API creates a CourseBuildJob and returns 202 Accepted.
  3. Background task calls Gemini (if key present) or Mock provider.
  4. Provider returns structured JSON matching Pydantic schemas.
  5. Service saves one draft artifact per requested type.
  6. Teacher edits and publishes selected artifacts.

9. How to use it

  1. Start backend and frontend.
  2. Optional: set GEMINI_API_KEY in backend/.env. Without it, mock drafts are generated.
  3. Log in as class/subject teacher.
  4. Open Subjects → select subject → save or upload syllabus.
  5. Click Generate AI drafts.
  6. Review/edit drafts → Publish selected ones.
  7. Log in as enrolled student → open the published subject → view AI course content.
Runtime note: During validation, a stale process briefly blocked port 8000. A clean backend on port 8001 was used successfully for API verification. If the frontend proxy (port 5173 → 8000) fails, restart the backend cleanly on 8000 or temporarily point the proxy/API URL to 8001.
